Every app I wanted to build needed the same hard parts: sign-in, sync across devices, working
offline, and keeping people's data private, even from me. Building those again for each app would
mean getting the hardest parts wrong more than once. Starling is that foundation, built once.

I design and build it myself, for the kind of apps I want to exist: ones I can confidently share
with friends, family and anyone else.

An app gets a local database, sign-in with an emailed code, and end-to-end encrypted sync, all set
up with one function call. You pick a passphrase once on each device, and from then on your data
moves between your devices without the server ever being able to read it.

## How it works

Each app reads and writes its own SQLite database on the device, so everything is instant and
works offline, and changes sync in the background. Because the storage is plain SQLite, Starling
runs anywhere SQLite does, which is how [Notebook](/projects/notebook) works both in the browser
and as Mac and iPhone apps. Before anything leaves the device, it's encrypted with a key only your
passphrase unlocks, so the server only stores and relays data it can't read. When two devices edit
the same record, the changes merge on the device, so edits to different fields both survive. One
small server on Cloudflare handles sign-in and sync for every app.

Notebook and Plates both sync through it today, and I plan to keep improving it over time. I've
got my eyes set on things like private groups, and on shaping it into a library other developers
can build on too.
